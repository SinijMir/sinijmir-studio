## Задача

Построить проверяемую основу мобильного мессенджера: отделить клиентское приложение от серверной логики и связать ключевые пользовательские сценарии через API.

На этом этапе важно было не имитировать готовый сервис, а последовательно проверить регистрацию, вход, поиск собеседника, создание диалога и обмен текстовыми сообщениями.

## Решение

SinijMir Studio разработала Flutter-клиент и отдельный development-сервер на Node.js. Мобильное приложение обращается к REST API, а сервер обрабатывает пользователей, прямые чаты и сообщения.

Данные прототипа хранятся в локальном JSON-хранилище. Это осознанное решение для текущего этапа проверки сценариев, а не заявка на production-инфраструктуру.

## Технологии

- Flutter и Dart для мобильного клиента;
- Node.js для development-сервера;
- REST API для обмена данными между приложением и сервером;
- локальное JSON-хранилище для прототипирования серверных сценариев.

## Особенности реализации

- регистрация, вход и хранение пользовательской сессии;
- поиск пользователя по номеру телефона;
- создание и отображение прямых чатов;
- получение и отправка текстовых сообщений;
- модульное разделение экранов, моделей и репозиториев данных.

## Результат

Собран рабочий контур продукта для локальной разработки: мобильный клиент и сервер обмениваются данными в основных сценариях общения. Проект остаётся в разработке и не позиционируется как готовый публичный мессенджер.

Следующий технический этап — production-хранилище, усиленная авторизация и доставка сообщений в реальном времени.
